# 插件统计实现与边界

插件在后台向服务端 `/api/v1/analytics/events` 发送白名单事件；控制台 `/admin/#/plugin-analytics` 通过登录后接口查看聚合与设备列表。服务端代码位于独立的 MetaOnticVideoService 仓库。

只有正式版 `X.Y.Z` 参与统计：测试版（如 `3.22.9-test.2`）与未注入版本号的开发构建直接返回空实现，不写匿名身份文件、不起定时器、不发任何请求，也不占用队列。

## 不影响创作

工具入口不等待网络、身份文件或上报结果；异常不改变工具结果与错误。队列最多 200 条，每批 20 条，默认延迟 1 秒发送，请求 1.5 秒超时，每条最多尝试 3 次。定时器不阻止退出，卸载取消请求并丢弃队列，不等待补发。安装监听只旁路观察宿主操作，读取安装来源最多等待 1 秒，监听、归类或排队失败都不会影响安装、加载与工具执行。设置页「高级设置 → 使用统计」可关闭；开发验证可设置 `METAONTIC_VIDEO_ANALYTICS_DISABLED=1`。

## 真实安装完成

`plugin_installed` 只认宿主 `plugin-manager/operation` 的真实安装结果：操作目标为本插件、阶段为 `enable`、已进入 `settled`、`changed=true`、没有错误，且 `application` 为 `applied` 或 `restart-required`；失败、取消与 `overridden` 都不计数。事件按宿主操作 ID 在本地幂等，时间与版本优先采用宿主操作记录；该通知现在仅作为设备首次登记的候选入口；它与plugin_started共用持久化登记标记，更新及重装不会重复登记。

安装来源只上报固定枚举 `npm`、`tgz`、`directory`、`git`、`bundled`、`unknown`，由宿主安装记录归类；完整 URL、路径、凭据与原始来源字符串不上报。读取来源超时、失败或宿主未返回匹配记录时回落 `unknown`。

安装完成不等同首次启用：若安装后插件未激活、需要重启才能加载，或安装时没有启用，插件来不及监听，就不会产生该事件；后续首次加载仍由 `plugin_started` 识别。服务不可用、关闭统计、离线或退出丢弃会令数据不完整，但不会阻塞任何插件操作。

## 字段与统计口径

仅接收插件启用、真实安装完成、工具开始/完成、视频任务创建/终态事件，以及固定枚举的工具、模式、安装来源、状态、错误类型和调用耗时。附系统类型、内核版本、CPU 架构、取整内存、Harness 与插件版本。不包含对话、创意、提示词、媒体、API 密钥、用户名、MAC 或序列号。安装标识是本地随机 UUID，服务端仅存其 SHA-256；任务 ID 仅参与本地散列，不上传原值。身份文件在宿主数据目录 `state/metaontic-video/` 下写两份（`analytics-id.json` 与冗余的 `analytics-anchor.json`），只在两份都不存在时才分配新标识；删掉其中任意一份（手删、清状态）都不算新设备，下次读取会用幸存的那份把另一份补回来，两份对不上时以 `analytics-id.json` 为准并自愈。首次初始化和修复均持跨进程独占锁，拿锁后重新读取主文件和锚点，以临时文件原子替换；只恢复确认已退出的本机进程锁。活跃锁有界等待约1秒，读写失败不永久缓存空身份，下次上报重新尝试。多进程实测覆盖12个进程同时首次初始化。仍然不是硬件指纹：整个 `state/metaontic-video/` 被清掉、或把整份宿主数据目录复制到另一台机器，会分别造成多算一台与两台算一台，这是有意保留的隐私取舍。首次成功接收代表首次启用，不是下载量或人数；安装完成来自宿主真实安装操作，包含首次设备登记的候选入口，更新和重装不再重复上报。关闭统计、旧插件、离线或丢弃事件都会使数据不完整。

服务端按安装标识与事件 ID 幂等入库，限制请求体和 IP 频率，统计接口要求控制台登录。原始事件默认保留 90 天，首次启用记录保留；请求日志仅记录事件数。按北京时间聚合，控制台展示累计/新增/活跃匿名设备、每日趋势与登记来源历史样本；不把一次性登记展示为启动或安装频次；视频任务数依据创建事件，终态重复查询不重复计数；调用耗时不是上游纯生成耗时。

## 平台与验证

Windows/macOS 共用 `node:os`、`node:path` 与随机标识实现，状态位于宿主数据目录，不硬编码开发机路径。插件统计测试 19 项覆盖正式版判定、白名单、掉线/超时/重试、队列上限、禁用、退出、热加载去重、工具失败隔离、真实安装完成与来源脱敏，以及匿名身份的并发/单文件残留/损坏与冲突自愈；独立服务端 15 项统计测试覆盖幂等、并发、鉴权、校验、限频、时区和安装事件。服务端完整 195 项测试与 ruff 检查通过、前端构建及 SEO 检查通过；插件完整 767 项测试、类型检查与构建通过。尚未由这些自动测试覆盖 Windows 桌面实测或真实付费生成。本机另做过一次真实路径核对：对已有的 `analytics-id.json` 调用 `analyticsIdentity()`，旧标识原样保留、只补出同值的 `analytics-anchor.json`（老版本升级到本版不会换设备）。

## 单设备仅登记一次

设备登记事件plugin_started与plugin_installed共用state/metaontic-video/registered-<匿名ID散列>.json。排队前以wx独占创建，Windows/macOS共用文件系统独占语义；并发进程只有一个能放行。先写标记再发请求，结果不明、失败、退出、权限错误均不自动补报或清标记，宁可漏记。两类入口使用相同确定性eventId，服务端按匿名身份与事件ID继续幂等。工具调用和视频任务统计不受此规则影响。

普通重启、升级和卸载重装若保留宿主状态目录，不会重复登记；新协议首次运行会创建标记，已有匿名身份仍由服务端合并原设备，不增加累计设备数。整个匿名身份与登记状态清空后会被视作新实例，本方案不使用硬件指纹，不能声称物理设备永久唯一。旧协议已入库的历史事件不删除。安装/启动事件今后不能再作为安装频次或启动频次指标。

## 管理端版本核验

客户端版本属于自报字段，不证明客户端真伪。服务端保留原始上报，管理端对照npm官方正式组合包及发布时间：未核验版本单列，不混入某个已发布版本分布；设备列表另展示最近匹配已发布清单的历史上报。历史事件已过保留期且无可用记录时显示未知，不把异常值强行改为最新版。

官方清单内置已确认快照，由服务端后台每10分钟刷新；失败沿用快照，采集与查询不等待外网。新版本后续发布不使发布之前收到的异常上报自动变成匹配。版本核验不增加设备、调用或内容采集，不修改客户端、不改变设备去重。管理端仍展示全部匿名实例，未核验版本不等同恶意或无效设备。


## 创作结果扩展协议

扩展事件独立使用 `POST /api/v1/analytics/outcomes`，不与原 `/events` 批次混用。
两类批次共享队列总量上限、发送互斥、超时、退出取消和有限重试。旧服务返回404/405后，本次插件实例停用扩展事件，原协议继续；服务端500、离线或关闭统计均不影响工具执行。升级服务前不会因扩展字段拖累旧批次。

事件仅包含固定阶段、操作、状态、错误分类和有界数值，沿用匿名设备标识。流程关联值在本地做带设备身份的SHA-256，不上传原项目、目录、会话、操作或任务ID。请求日志对两个端点均只记事件数，验证失败的请求也不记录正文；通知阅读、关闭、点击继续只存在插件本地。

- `outcome_started`：新生成流程开始，沿用分段目录作为本地关联值，续做不重复计新流程。
- `outcome_finished`：创意、剧本、素材、分镜、提示词保存、人工批准、独立终审、生成、续做、分段取件、合并及宿主可观察的安装/更新结果；只读read/next/status不算创作完成。批准、需修改、取消、待处理、暂停、失败分别保留。阶段次数是操作次数，不是人数或产物数；重复批准可作为一次操作观察。
- `first_segment_ready`：首次提交并在同次调用获得第一段成功结果的等待时长；不混入已提交任务的续查，不用失败或未知结果作成功样本。此时长包括该调用内必要的参考图处理，不承诺上游纯排队/生成耗时。
- `video_ready`：结果状态为完整本地成片，文件存在且非空；暂停、部分、上游链接、下载或合并失败均不计。段数取结果分段数，成片秒数只用媒体探测值，缺失不以计划时长补造。
- `video_delivered`：该会话已记住的完整本地成片在宿主 `deliverables/presented` 事件中以同一路径实际登记。文件名/大小相同不足以采信。正文内联链接、改名副本、窗口重建后丢失的会话观察可能少报；展示不证明观看或验收。

同流程就绪与卡片展示分别使用确定性事件ID，重复续做/展示复用原ID，服务端继续按设备+事件ID幂等，视频数量还按设备+流程去重。设备首次登记规则不变，业务事件不会清除或绕过登记标记。

管理端将匿名设备、上游任务成功、本地成片就绪、卡片已展示分开。新增指标仅覆盖升级后成功采集的样本，无样本显示“—”，无扩展样本日期不画成零。成片就绪率的分母为本期观察到开始的生成流程，分子为其中本期已就绪的同设备同流程；跨期开始的成片不进入该分子，不能用于全量创意转化率或人员转化率。

安装结果只来自当前插件存活时收到的宿主终态；首次安装未加载、禁用、切换/重启期间的失败可能不可见，因此不计算全量安装成功率。宿主明确区分update时才分为更新，不根据版本或文件路径猜测。

服务端模型新增字段必须同时通过`SCHEMA_PATCHES`补老库，旧事件字段保持可空；原始事件沿用现有90天保留策略，匿名设备记录保留。所有字段处理与文件操作共用Windows/macOS实现，无额外本机命令；本轮自动测试不等于Windows桌面实测。
