# 审批材料展示核对

发现并修复：

- 创意待批准时原响应不携带完整可读材料，而审批卡片只提示回看正文。现返回绑定产物修订号的approval_material，包含创意全部可读内容。
- 专业next与read(stage)绕开projectResponse，可能丢失剧本完整正文和展示指令。现统一补充同源材料；next保留原任务字段，不改变调度协议。
- 人工问题服务缺失、取消或未答时补回当前材料与未获批准提示，保留项目，禁止将未答当同意。
- 过期产物不作为可批准正文返回；批准入口继续检查项目revision、产物stale和已有批准复用。

核对未发现同类缺口：普通脚本/分镜由storyboard审核守卫检查实际用户可见内容；分段结果由segment-review检查真实链接，批准记录绑定完成段数与末段任务；费用确认仍独立，未替代脚本/结果审批。

限制：专业创意和剧本目前通过工具材料与提示词要求先正文展示，尚未增加会话正文事件的强制匹配守卫。因此不能把返回approval_material当成用户确已看见，也不能宣称模型必然遵循。未进行真实桌面审批或付费调用。

验证：构建、类型检查、688项自动测试及diff检查通过，新增覆盖创意完整材料、next/read(stage)同版材料、长剧本不截断、过期材料不展示。Windows/macOS共用响应逻辑，无平台专属文件或进程操作；未做双平台桌面验证。未发版。
