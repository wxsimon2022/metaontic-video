# 构建与运行标识

每次构建从源码、技能、版本、锁文件及构建入口计算内容摘要，注入宿主和客户端，并生成 dist/build-info.json，记录版本、摘要及各入口和双份 locale 的 SHA-256。任何输入改变后，局部构建自动扩为完整构建；失败先移除清单，避免将半成品误认成完整构建。

npm pack 的 prepack 验证源码、版本、清单和实际文件；未构建或文件不符立即失败。正常打包不得使用 --ignore-scripts 跳过此检查。

本地安装使用 npm run install:local -- desktop（默认 desktop）。先检查活动视频，再构建、校验、打包。成品路径包含完整构建摘要，避免同版本覆盖同路径 tgz 后 pnpm 继续使用旧缓存；安装后逐项核对托管文件。不修改版本号、不发布、不卸载、不改业务配置。Windows 使用 cmd.exe 调用 .cmd，拒绝 shell 元字符；macOS 用 spawn 参数数组。两平台都使用 node:path 和系统用户目录。

只读 /metaontic-video/runtime-version 报告当前执行模块的内嵌标识与磁盘清单，沿用宿主本地服务认证。在线更新只有宿主返回 applied 且实时查询的目标版本、运行摘要、安装摘要均一致才显示完成。查询和响应体均有超时；旧宿主/端点缺失/状态不明显示已安装待确认，不重复安装、不无证要求重启。video_config 的 runtime 提供实际执行模块标识，不能将磁盘安装成功当作热加载实测。

自动回归覆盖源码/版本过期、文件篡改、同版本不同摘要、缺失标识、查询与响应体挂起，以及 applied/pending 区分。成品安装检查同时核对模块可导入、宿主/客户端的内嵌摘要、清单版本及文件 SHA-256；它属于临时 profile 自动检查，不等同真实桌面热加载验证。本次未运行 Windows 桌面验证，也未对真实桌面安装新包。
