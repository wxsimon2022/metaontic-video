# Film Director V2 结构迁移

创作域为 src/businesses/film-director，视频执行域维持 src/businesses/video。两个现有助手装配两业务，通过 film_project 提供独立创作项目。角色采用同一助手顺序切换职责，未接入独立子 Agent 运行时。

已实现：15–3600秒创作项目、JSON权威状态、阶段提交、版本冲突保护、真实用户问题服务批准创意和剧本、下游失效、基础时间轴/引用/覆盖校验、不可变快照、JSON与Markdown返回。Markdown当前为结构化数据可读导出，不是完整排版剧本。

项目文件保存在 dshHome()/DATA_DIR/film-projects/<会话哈希>/<UUID>。project.json为唯一原子提交点，快照先写入；崩溃遗留快照不算完成。进程内互斥，不承诺多进程写入安全。无独立服务、数据库或新增运行依赖。

尚未实现：完整JSON Schema、独立角色与七技能文件、章节批调度、工件manifest与完整性恢复、实体级依赖、回滚工具、语义Reviewer自动修复、导出文件落盘、实际视频制作计划适配。不得声称已满足V2全部验收条件。

平台：使用node:path、随机临时文件与rename，无Shell命令和平台特有路径；Windows文件占用导致rename失败时原提交保留。仅本机自动测试，未做Windows或Harness桌面实测。未发布、未安装。

提示词参考本地ALL_AGENT_PROMPTS.md，公共专业方法在creative.ts，film_project实际工具契约单独注入；不复制未实现的文件信封与子Agent承诺。冲突以V2设计和现有产品审批为准：业务修复上限2轮，审核严重级别统一小写，程序兼容大小写blocker。画布文本入口明确按生成段聚合表格，避免一镜一行破坏现有解析。不新增平台相关调用。

## 编排与制作桥接

film_project.next由程序返回当前允许动作、专业职责和直接依赖数据；提交仍由确定性前置条件阻止越阶段。compile重验全部阶段、批准版本、时间轴、引用和覆盖，使用video业务estimatePlan分段。输出每段镜头映射及实际specification，绑定既有video_project项目。重复同版本同规格编译复用绑定；角色图选择、脚本展示审核、费用确认仍按既有执行链。创作revision变化阻止旧关联新增生成，原已提交查询与交付不受阻。

当前编译覆盖15秒至60分钟完整项目，按模型单段能力安排生成与续拍；参考素材需在既有prepare/review阶段补齐。阶段上下文通过next返回，宿主仍为同一助手，无独立模型子任务或自动背景调度。完整Schema、跨进程事务、实体级失效及章节执行仍属于后续工作。

## 角色与意图路由

roles/下八个独立TypeScript提示词由构建打包，不依赖运行时读取源码文件。每份定义职责、方法、输出和边界。film_project route支持19类显式意图，由主控理解语义后选枚举；不用关键词匹配擅自判定执行意图。route只读，返回角色、scope、依赖、批准缺口与专业指令。next复用同一提示词，assets阶段顺序采用人物及场景两份职责；无需独立子Agent运行时。局部修改缺ID标needs_input，已知镜头/人物/场景ID不存在直接拒绝。正式提交仍使用现有校验和审批。

测试覆盖全部意图、八份提示词、局部目标缺失、非法ID、批准缺口、只读行为。未调用付费模型评估实际创作质量，未做Windows/Harness桌面实测；纯字符串编排不新增平台依赖。

## 内容质量提示词

共享content-quality.ts约束已进入公共创作指导、画布文本写作及creative/screenwriter/storyboard/prompt-engineer/reviewer角色。重点为因果、信息增量、动作可见性、必要留白、对白预算与结尾回收；按片种区分表达方式。保持分镜表列名和生成段行数协议，不增加付费调用。构建与582项回归通过；未用付费模型进行成片质量对比，不能据此保证生成效果。提示词字符串变化无新增平台调用。

中心表达与画面深度：共享规则要求脚本明确核心表达、内容主线和结尾变化，逐段用行动/细节/证据支撑主题；逐镜明确站位、主动作起止、反应、道具状态和衔接。画布入口保持表格协议，增加可读主题说明。构建与582项回归通过；尚未做付费生成效果对比，不据此保证成片内涵或执行准确度。

八角色短视频专项规则集中在roles/short-video.ts，逐角色入口独立装配；公共描述基准同时进入对话与画布文本入口。统一风格/节拍动作/声画/衔接协议，避免MiniDV、胶片、8K和渲染器标签混同实际能力。保留生成段表格、工具参数和付费审批。构建与582项测试通过，未进行付费模型创作质量对照或桌面验证。无新增平台依赖。

CREATIVE角色采用用户提供的V3.0专职契约，移除该角色对公共编剧/逐镜写作规则的直接拼接，保留创意视觉证据而不提前分镜。新稿输出完整V3字段，beats统一命名，transition_logic兼容加入structure。已有旧稿兼容读取；提供structure时程序校验非空、稳定唯一section_id、正整数时长及全片总和，approval_questions最多3项。机器校验不等于语义通过；主题、事实、可见证据由专业审核处理。构建、582项既有测试与新增创意校验用例通过，未安装、未调用付费模型。

## 专业角色提示词与审核协议

Creative 使用 V3.0，其余七个角色使用 V3.1 专业职责提示词。人物、地点、场次、环境状态分别引用稳定 ID；创意与剧本分别批准，提示词不能代替执行或费用授权。角色是助手的逻辑职责，当前工具不代表已注册独立 Agent 运行时。

新版审核支持八维评分、N/A 权重归一化、明确审核状态及问题复审状态。程序复算加权分和阻断数；未 VERIFIED 的 CRITICAL/MAJOR 问题阻止编译制作，失败报告可保存。旧审核协议保留兼容。提示词审核不能证明实际视频画面、声音或口型已经合格。

本次仅涉及平台无关文本、数据验证与编排判断，不新增平台路径或外部进程。构建与模拟测试在 macOS 开发环境执行，未进行 Windows/macOS 桌面安装验证，也未调用付费视频接口。


## V3.1设计方案整改与写作入口定位

根目录设计方案映射到现有业务目录，不新增无真实执行能力的Agent目录。八角色统一注入COMMON_CONTRACT，Creative提升为V3.1并保留原细化方法；新项目使用3.1严格字段校验，历史项目继续兼容。新增地点/环境状态/服装/道具/对白引用、原文与覆盖检查、来源版本绑定、复算审核与实际产物任务完成证据。审批持久记录批准/修改/拒绝；拒绝停止推进。导出返回可读Markdown及真实JSON指针、修订号、SHA-256清单，尚不自动写出独立导出文件。

对话入口原本将专业film_project设为可选，普通请求容易按旧全能流程直接生成分镜表。现改为15–3600秒完整新剧本优先按专业阶段推进，已有普通项目与极短片保持原流程，当前角色职责优先于全链路制作指导。SCRIPT_CRAFT同时注入编剧角色和公共写作方法，明确事件链、人物选择、潜台词、完整场景与交稿前局部重写。画布入口不读取skill，故同步注入共享方法，要求先完整场景剧本再制作表格，并提高输出预算；仍为一次文本请求，不伪称已运行多Agent。

旧技能入口改为按阶段读取参考资料，新增script-craft/professional-workflow/execution-workflow，移除强制切镜次数与声音层数，避免编剧提前承担摄影与模型提示词。保留普通制作的费用、角色图审核、未知提交防重与恢复约束；模板不再手写批准时间或将每镜当付费任务。两个技能通过skill-creator格式校验。

平台影响：均为平台无关提示词、数据结构与Node标准库操作，不新增Shell或硬编码平台路径。实际创作效果尚未通过付费对照样片验证，不能把自动测试通过当专业成片保证。独立模型Agent执行器、跨进程事务、按章后台自动生产及自动修复仍未实现。
