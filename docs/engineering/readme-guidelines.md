# README 维护规范

README 是项目首页，帮助初次访问者了解用途、安装并开始使用。

## 固定结构

中英文保持相同顺序，每份不超过 60 行：

1. 标识与简介：Logo、插件名称、语言切换、一句话定位。
2. 核心用途：只保留「新手快速创作」「低成本长视频」两点，附一句计费说明。
3. 在线安装：Harness 入口、中国镜像源当前正式版链接优先，其次列 Gitee 正式成品与 GitHub 同版备用链接。宣传文章、插件市场介绍和使用说明的安装推荐也遵循相同顺序。
4. 开始使用：最多三步，说明设置、助手选择及审核制作；最多一个简短示例。
5. 相关链接：在线说明书、问题反馈、CHANGELOG、开发文档及许可。

## 内容边界

- 每段只表达一个要点，不堆砌卖点、参数或专业术语。
- 不添加版本更新条目、最新更新、路线图、临时状态、故障排查记录或验证结果。
- 不添加架构图、源码目录、Agent/Skills 实现、内部协议或发布命令，开发内容写入工程文档。
- 不逐项追加功能说明、模型能力表和完整操作教程，使用内容统一维护到在线说明书。
- 不添加下载解压、本地路径安装步骤或版本选择；市场配置等其他安装方式放入使用说明书。
- 不承诺模型必然成功、人物绝对一致或固定低价；不把文档产物写成已生成视频。
- 不引用本地说明书、PDF、价格资料及未公开成品。

## 修改与发布

- 新功能默认更新使用说明书，README 仅在定位、安装入口或首次使用步骤改变时修改。
- 中英文同时维护，避免同一信息重复出现；功能细节以相关文档链接承接。
- 发版时同步 README 中的在线安装链接，确保中国镜像源链接对应当前正式版；版本变化写入 CHANGELOG、releaseNotes 与 Release。
- 修改后检查行数、Markdown 结构、仓库相对链接及镜像/Gitee/GitHub 安装链接；纯文档修改无需构建或重复运行业务测试。
- 中国镜像源直链必须是 `registry.npmmirror.com` 上可直接安装的正式版 `.tgz` 地址。发版前验证 npm 官方版本、镜像版本及成品完整性一致；不要把 npm 包信息页、registry 元数据接口或未经确认的 `latest` 地址当作安装包链接。
