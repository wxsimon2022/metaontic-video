# 包名迁移与设置页回归修复

## 原因与范围

`metaontic-video` 改名为 `dsh-metaontic-video` 后属于两个包身份。宿主会保留并启用两个 bundle；它们继续使用相同的配置、预设、工具和面板 ID，不能把 npm 安装成功视为 Harness 迁移成功。此前的自动安装检查手动改写了启用列表，漏掉实际“双包同时启用”状态，未证明桌面设置页可见。

## 实现

- 新版宿主入口先核对 bundle 清单；存在旧包启用冲突时等待，不注册第二套工具。旧包停用后再装配新版业务；退出时清理等待与工具，不晚注册。
- 新版客户端在共享字典、面板和工具视图之前挂载独立的迁移设置页。确认没有冲突后装配完整设置；清单异常时保留可见诊断与重新检查入口，不静默显示空页。
- 双包冲突时通过宿主 `setBundleEnabled` 停用旧包。用户先结束任务，再点击切换；按钮防重复操作。重新读取清单确认生效，拒绝或未生效时保留页面。仅实际 `restart-required` 才要求重启。
- 不卸载旧包、不直接改 profile 文件、不改 API密钥、不删除任务和素材。保留已安装旧包作为回退资料，禁止两套同时启用；不将“停用”描述为旧包已卸载。
- 正常界面挂载失败仍提供诊断页。页面关闭或宿主重载期间完成的异步检查不晚注册组件。
- v4.0.0 已撤回；README 与在线索引恢复 v3.32.0，历史标签保留。撤回清单阻止市场重新收录、发布脚本续跑及 CI 重建公开发行版，不修改已公开标签。

## 验证与边界

构建通过，665 项自动测试通过，实际 Harness JSON Schema 检查 11 个工具通过，git diff --check 通过。9 项迁移测试涵盖双包启用、新装、旧包停用、拒绝、回包成功但未生效、宿主要求重启、清单异常、关闭期间异步返回、宿主延迟注册和清理。设置页使用实际成品客户端和 React SSR 检查可见文案及切换后完整设置挂载。

全量验证发现旧画布测试先看到生成完成、再异步写入发布结果的竞争，已让该用例等待所断言的同步状态，无生产行为变更。

Windows/macOS 共用宿主 API 和注册机制，不引入路径、进程或包管理器平台差异。此次没有操作用户的本机启用状态，没有安装修复包、没有发布新版本，没有实际桌面迁移和真实视频调用验证；自动测试不能代替这些实测。后续发版必须使用新版本，完成双平台成品检查，并另行核对真实 Harness 的迁移入口与设置页。
