# 对话脚本耗时排查

## 观察依据

检查 2026-11-17 本地一次 60 秒专业项目的阶段快照和 09:15–09:29 UTC 请求日志。只统计该时间窗口，排除测试产生的毫秒级模拟文本模型记录，不输出用户脚本或密钥。

- 创建到正式剧本保存：224.68 秒；到全链终审：601.88 秒，含创意与剧本审批、内容生成、阶段切换和修正，不是纯模型生成时长。
- 19 次 film_project 调用中有 8 次失败；非人工等待调用耗时中位数 2.27 毫秒，最大 5.737 毫秒。两次审批调用分别等待约 19.15 秒和 7.18 秒。
- 因缺少宿主逐次模型首字、推理和解码指标，不能把所有工具调用之间的时间都归因于模型，也不能承诺减少固定秒数。

## 优化

`responseMode:"compact"` 返回项目与产物版本摘要、任务摘要和下一阶段完整必要输入，避免把全部历史产物及旧任务输入反复回传。完整内容仍存盘；`read(stage)` 精确补查单个材料，`read(responseMode:"full")` 保持完整恢复兼容。写操作默认 compact，完整 read 维持原有默认行为；需要完整写入返回的调用可显式选 full。角色与工具说明引导正常推进使用 compact。工具已返回 nextTask 时不再重复调用 next/read。

submit 自带完整校验，失败时在同次调用集中返回缺失数组等问题；取消每稿强制 validate→submit 的额外模型往返。validate 作为可选独立检查保留，结构、引用、时长、版本与审批门禁不放宽。

用上述项目快照回放比较同版结果的 JSON 字节数（不调用模型或付费接口）：

| --- | ---: | ---: | ---: |

| 资产 | 102892 | 57892 | 44% |

这些是返回体大小变化，不是实际模型速度的 A/B 测试结论。创意/剧本批准、付费同意、分镜图展示和逐段审核仍保留。没有削减正式剧本或省略下一阶段所需材料。

## 验证与平台

覆盖精简响应的依赖完整性、不可变状态、单产物读取、一次提交失败后的项目修订保持，以及旧完整返回兼容。实现只涉及通用对象投影与工具协议，不更改 Windows/macOS 的路径、进程和安装行为；未做实际桌面耗时或真实模型压测。
