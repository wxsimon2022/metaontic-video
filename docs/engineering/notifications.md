# 插件消息通知

控制台「插件通知」填写标题（80字内）和内容（1000字内），可选填跳转链接（1000字内），可保存草稿、发布、下架或删除。最新发布的消息优先展示，一次显示一条；关闭后显示下一条。编辑或重新上架相同 ID 不重新提醒已关闭用户，新消息须新建。

公开只读 `GET /api/v1/notifications` 返回统一信封及 `data.items`，最多50条已发布消息。无需注册、密钥、设备标识或握手头。控制台 `/api/v1/admin/notifications` 的 GET/POST/PUT/DELETE 均需管理员令牌，编辑与删除用 revision 防并发覆盖。

插件首页与设置页共用消息状态，页面打开时同步、停留每5分钟刷新，5秒超时。断网、HTTP错误、业务错误、损坏响应及响应体挂起均静默保留缓存，不影响创作与设置。不阻断视频任务，不发系统通知或弹窗。标题和正文只渲染纯文字，不执行远端 HTML。配置 action_url 时整条消息是可用键盘聚焦的链接，用户点击后打开新窗口；未配置则为普通消息。仅允许完整 HTTP/HTTPS 网页地址，拒绝脚本、文件及带凭据地址。关闭按钮在链接之外，关闭不导航。收到的消息及关闭记录保存在当前 Harness 本机浏览器存储，不向服务端回传已读、关闭状态或消息副本。离线保留本地消息；服务端下架/删除在下次成功同步后移除。清空宿主本地存储会失去关闭记录，可能再次显示；不承诺跨设备同步。

服务端启动自动创建新表；兼容旧表遗留的 action_text/action_url/priority 非空列，简化表缺列时由 SCHEMA_PATCHES 补齐。action_url 复用已有字段，无需额外迁移。通知及可选链接服务端已部署验证，插件正式版与双平台自动安装结果见 release-4.2.5.md；后续本地安装按用户明确要求执行。服务端保存管理端原始消息以供新设备下发，不保存逐设备收件箱。

Windows/macOS 使用相同浏览器 API，无路径、进程或额外依赖；已执行本机构建与模拟回归，尚未进行两平台真实桌面验证。
