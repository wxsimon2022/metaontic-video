# 最低支持版本策略

普通更新沿用原有提示和两次确认安装。安装了策略能力的客户端低于远程最低版本时，设置页及创作侧栏显示不可忽略的更新提示，工具入口拒绝新的创作写入、独立文本复审、图片生成、视频生成和续拍。不会自动安装、卸载插件、清除配置或重提任务。

已有视频通过 video_status 查询和取件；图片按原 taskId 取件；防重核对、费用估算、项目读取与导出、已有专业任务状态回写及已生成分段的审核继续开放。resume 可能新增付费调用，因此不能用它绕过限制；需要先升级再继续生成。

## 运维操作

策略文件为 config/update-policy.json，读取 Gitee 和 GitHub 的 master 分支公开文件（contents API，base64 解码；不依赖 raw 下载域名），不依赖安装包内副本。两个仓库应保持相同内容。当前最低版本为 4.1.0。

1. 先发布并核对要提升到的正式版成品。不能先提升门槛再发布。
2. 修改 minimum_version 为已发布的正式版号；revision 在已有最大值上加一。
3. 按仓库推送流程同步该文件到两个仓库。只修改策略不需要再发布插件包。仅修改本地文件不会影响用户。
4. 在线客户端界面及受限制的工具调用约每五分钟重新检查。双源取最高 revision，同 revision 内容冲突时保留原策略。关闭界面后首次创作工具调用仍检查。
5. 撤销一次限制时，用更大的 revision 将 minimum_version 降到已发布的支持版本；不能倒退 revision 或删除文件来撤销。

提升门槛前客户端会核对中国镜像、Gitee、GitHub 中至少一处存在该正式版的可安装成品元数据。它只验证发布信息，不承诺用户所在网络一定能够下载。无效 JSON、其他包名、预发布版本、不存在的目标、超时及双源冲突都不启用新策略。

缓存最后接受的策略。已知限制在断网或检查失败时保留；首次启动且没有策略缓存时，离线不凭空封禁。网络恢复后继续检查。网络策略不是防篡改或授权系统：本机代码/缓存可被用户修改，不能保证所有离线客户端立即执行。

## 覆盖范围与验证

旧版没有这段协议，无法被追溯强制升级；用户必须先安装包含该能力的版本。开发源码加入能力不代表当前已发布的同版本包已改变，也不覆盖公开成品。本次没有修改版本号、发布、推送策略或安装到本地。

主进程缓存路径由 dshHome 和 node:path 组合，位于 state/metaontic-video/update-policy.json，临时文件唯一并原子替换；浏览器独立缓存同一协议。Windows/macOS 共用实现，不调用系统命令。未在 Windows/macOS 桌面实际验证在线升级，不以模拟测试代替安装验证。

回归 tests/update-policy.test.mjs 与 tests/optional-update.test.mjs 覆盖版本边界、断网/重启、并发合并请求、未发布目标、双源冲突、策略撤销、超时、付费入口拦截和更新确认。不会调用真实付费接口。
