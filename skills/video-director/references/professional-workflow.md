# 专业数据与修订协议

## 运行边界

film_project当前以同一个助手切换八种专业职责。next/route返回角色指令、直接依赖、版本、范围和未知模型能力档案；不代表已运行独立Agent。不复制设计稿中的假设API或另建一套状态。

顺序：creative→批准→script→批准→assets→shots→prompts→review。submit的content是合法JSON字符串，expectedRevision来自最近工具返回。创意和剧本的修改/拒绝由真实问题服务记录，不手写批准标记。

## 规范字段

- creative：theme/logline、structure（section_id和duration_ms）、must_preserve、assumptions等完整角色字段。working_title/story_beats等参考别名映射至统一结构，不维护冲突副本。
- script：screenplay为完整正文，chapters引用scene_ids，scenes含scene_id/chapter_id/duration_ms，characters使用character_id；dialogue为dialogue_id/speaker_id/scene_id/exact_text数组。参考稿dialogue_lines映射为dialogue。对白与旁白区分。
- assets：characters、scenes、locations、scene_states、props数组；场次引用location_id和scene_state_id。characters.costumes中的costume_id/character_id唯一且对应。人物参考图未生成就只列需求。
- shots：每镜含shot_id/chapter_id/scene_id/location_id/scene_state_id、character_ids/costume_ids/prop_ids/dialogue_refs、叙事目的、start_ms/end_ms/duration_ms、场面调度和声音。地点与场次一致，台词不丢失。
- prompts：每镜一条prompt，含shot_id/location_id/scene_state_id/duration_ms/generation_mode/dialogue_refs。提示词展开身份与环境锚点，原话逐字保留，不能写“同上”。
- review：review_id/review_stage/review_status、reviewed_revisions、八维scores、issues、delivery_allowed、blocking_issue_count、review_scope和unverified_items。reviewed_revisions使用creative/script/assets/shots/prompts的实际修订号。

时间为整数毫秒，[start_ms,end_ms)，duration_ms=end_ms-start_ms；镜头从0连续覆盖目标时长。场景、章节总预算同样闭合。source_revisions由提交运行时记录，自带时必须与实际依赖一致。

## 修订与复审

先read，再route意图与entityIds定位；revise支持已有assets.characters/assets.scenes、shots.shots、prompts.prompts实体替换，不擅自宣称可修改任意registry集合。修改地点/道具等完整资产对象时用submit聚合对象。对白改动由Screenwriter修改script并重走剧本批准。

上游改动会标下游stale，定向修订返回affected_shot_ids供局部重写；程序仍要求相关阶段完整对象复核，不等于自动完成局部重建。保留章节、场次、人物与镜头ID，不能把一个人物换装拆为新人物。

问题记录证据、位置、责任与复审条件；未复审不标VERIFIED。PASS/PASS_WITH_WARNINGS只在范围完整、无阻断且分数满足时交付。失败报告可保存，但不能编译制作。长片先全片结构，逐章草拟并保留连续性摘要；当前阶段提交需完整聚合，部分完成明确标PARTIAL，不冒充整片完成。

## 实际制作

逐镜提示词是创作任务单位，实际付费段使用compile返回的映射。当前执行器可能将多个镜头放入同一段，不能擅自把“每镜提示词”变成每镜一次付费调用。独立镜头生成方案需Director重规划，并走真实计划与费用审核。

compile只编译、关联video_project，不付费、不生成视频。随后先读取execution-workflow.md，补齐参考素材、示意图、制作脚本与实际调用预算，video_project审核通过后才由视频工具发起费用确认。


## 上下文、复审与制作边界

next/route每次携带original_idea、target_duration_ms、project_spec、approved_revisions，不依赖聊天记忆恢复用户要求。create的projectSpec参数为JSON字符串，只填已知规格与硬约束；未知项由工具标UNKNOWN。分镜参考execution_plan的真实分段边界，该计划不等于已付费或模型效果保证。

最终通过报告必须是FINAL_REVIEW，review_scope覆盖creative/script/assets/shots/prompts，适用评分不得用null跳过。重大问题保存到运行时issue_registry，不能从下一份报告删除、降级或自标VERIFIED。问题初始OPEN；责任产物真实改版后提交RESOLVED报告。Reviewer对当前版本按复审条件实际检查，调用verify_issue，content含evidence、review_revision与source_revisions，expectedRevision使用最新项目修订。工具登记版本和时间后，再提交完整终审报告。责任角色使用director/creative/screenwriter/character/scene/storyboard/prompt-engineer/reviewer规范名。

compile禁止在生成段边界截断完整镜头与台词，同一生成段不能混合不受支持的多地点组合；遇SHOT_SPLIT_REQUIRES_STORYBOARD_REVISION或MULTI_LOCATION_SEGMENT_REQUIRES_REPLAN，返回Storyboard按execution_plan重新规划，再更新提示词与审核。不得绕过错误重新复制整段台词。独立镜头执行器未接入，不承诺任意分镜自动转成任意模型请求。

项目规格已锁定的画幅、清晰度和目标模型必须与制作一致。写入使用跨进程文件锁；PROJECT_LOCKED表示其他进程或中断写入需检查，不能按超时盲删锁或清空项目。只有确认持有进程已停止且没有活动任务，才能进行人工恢复。

## 作品类型配置

work_type与visual_style（视觉风格）、narrative_mode（叙事方式）、generation_mode（生成方式）独立。类型为DRAMA剧情、COMEDY喜剧、LIFESTYLE生活Vlog/氛围、DOCUMENTARY纪录/知识、COMMERCIAL产品广告、PROMOTIONAL品牌/地域宣传。用户已明确就采用；未明确推荐一个方向，合并到创意确认，不把推断当批准。create的projectSpec可带work_type与narrative_mode；配置修订由系统绑定，next/route返回work_profile及当前职责的类型规则。新项目在创意批准前须明确类型；旧项目缺少该字段时沿原流程，不强制迁移。

修改类型用configure_profile，projectSpec为仅含work_type与可选narrative_mode的JSON字符串，expectedRevision来自最新状态。修改保留原材料并将全部标为stale、清除原创意/剧本批准、使制作绑定过期；先按新类型重写创意再走审批，不能继续用旧版制作。类型未变化时不无故重写。

creative/script按角色指令增加type_details对象，填写当前配置所列字段的具体非空文本，不复述规则。六类侧重点分别是选择与后果、铺垫与回收、观察与感官节奏、证据来源与事实边界、卖点依据与使用过程、辨识细节与情绪载体。纪录和广告证据缺失标待核实，不编造。

终审增加type_review（work_type、profile_revision、checks）；每个criterion_id匹配work_profile.profile.review_criteria，给status与evidence。status为PASS、CONCERN或NOT_EVALUATED；CONCERN另带issue_id关联已有问题，艺术建议不伪装客观错误；未评估项不能通过终审。共同的版本、时长、引用、对白、用户硬约束仍须检查，不因类型放宽。类型规则不会保证实际生成质量，不自动调用视频。

## 工具异常与恢复

INVALID_TOOL_OUTPUT / value is not lossless JSON 是宿主输出协议错误，不代表项目未保存。create结果不明时不要重复create或擅自改走普通制作，先恢复已保存项目并检查返回协议。参数或材料JSON校验失败时只修正对应格式与字段，保留创意及已批准内容；重复失败不构成跳过专业审批的授权，改选流程须用户明确决定。
