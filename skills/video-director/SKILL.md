# 视频导演工作流

默认规格：**9:16 竖屏、15 秒、720p、中文同期声、真实生活感、无字幕、无 BGM**。

## 0. 先确认工具

生成能力来自 MetaOnticVideo 插件。动手前先看一眼当前会话的工具列表：

- `video_generate` / `video_extend` / `video_status` / `video_config`

工具不可用时，让用户到「插件」页安装/启用 **MetaOnticVideo** 并配好上游，再继续。不要假装已经生成。

## 1. 铁律：脚本确认前，不生成

1. 用户给一段创意后，你的第一份交付是**视频脚本**，不是视频。
2. 脚本必须完整展示给用户，并明确问：**「确认这版脚本吗？确认后我才调用 video_generate。」**
3. 用户明确确认前，**绝不调用** `video_generate`、`video_extend` 或任何生成工具。
4. 修改意见 = 未确认：改脚本 → 重新展示 → 再次确认；脚本变了，之前的确认作废。
5. 用户说「直接生成」也要先给脚本确认；没有脚本确认，不生成。

推荐用 `ask_user_question` 完成确认，选项固定为：

```text
确认这版脚本，开始生成（推荐）
先改一下，我再看看
```

- 用户选「确认」后，才可以继续写 `shots.json`、提示词并调用 `video_generate`。
- 用户选「先改」或直接提修改意见：问清改哪里，改完重新展示、再次确认。
- 如果 `ask_user_question` 不可用：把脚本和确认问题发给用户，然后结束回合等回复；不要在同一回合生成。

## 2. 接创意

- 用户会直接输入一段话（一句话或一段描述）。**不要追问一堆参数**；没说的按默认。
- 先把这段创意压成：一句话钩子 + 一句 30 字内梗概，再展开脚本。
- 只有创意缺主角、缺核心冲突到无法写时，才问 **1 个**问题；否则直接写。

## 3. 写脚本

在 `video-projects/<slug>/script.md` 写完整脚本，frontmatter 必须是：

```yaml
---
status: draft
approved_at:
approved_by: user
---
```

正文至少包含：

1. **一句话钩子**：前 3 秒的冲突/反常识/利益点。
2. **规格**：时长、画幅、平台、风格、声音、字幕。
3. **人物锚点**：年龄、脸型、发型、服装、体型、姿态、情绪；后续每镜复述。
4. **分镜表**：镜头、时间、景别、画面、台词、声音。
5. **完整台词**：按秒标时间点，谁说什么；15 秒约 25–45 字（4–5 字/秒）。
6. **声音**：同期声、环境声、音色、口音、语速；是否要 BGM。
7. **结尾**：反转/金句/定格反应；需要字幕就写字幕文案。
8. **限制**：不换脸、不串台、无文字水印、手部正常。

写作规则：

- 前 3 秒必须有钩子；结尾给反转或金句，不要用旁白解释笑点。
- 台词要像真人能说出口的短句；一个人说完另一个再接。
- **总时长 ≤15 秒的视频必须一镜到底（硬规则）**：不许为了「中间切一刀更好看」而拆成多镜/多段再拼（例如 15 秒拆成 8+7）；`video_generate` 也只调用一次。
- 只有这两种情况可以多镜：① 用户明确要求多镜；② 单条视频总时长 >15 秒需要分段生成（那是同一条视频的续拍延长，不是多镜拼接）。
- 每镜 ≤15 秒；超过单段上限就分段（4-15 秒/段，默认吃满上限、段数最少）。
- 不要在脚本里写抽象空词（「高级感」「氛围感」），写具体动作、光线、道具。

## 4. 展示与确认（硬门槛）

- 把 `script.md` 的**完整内容**贴给用户或摘要到「能直接判断」的程度：钩子、分镜表、完整台词、结尾、规格。
- 明确问出确认问题；不要用「要不要生成？」这种模糊问法。
- 用户确认后，把 `script.md` 的 frontmatter 改成 `status: approved`，填 `approved_at`（本地时间）和 `approved_by: user`，并在 `production.md` 记一行「脚本已确认」。
- 用户要求修改：改 `script.md`，把 `status` 改回 `draft`，清空 `approved_at`，重新展示并再次确认。
- 没有 `status: approved` 的脚本，不允许进入生成。

## 5. 确认后：落镜头和提示词

1. 写 `shots.json`：每镜 `id`、`seconds`、`shot_size`、`cast`、`dialogue`、`prompt_file`、`task_id`、`clip_path`、`status`。
2. 写 `prompts/NN-*.txt`：每镜一份完整提示词，按八块公式：
   规格 → 场景 → 人物 → 镜头 → 动作与台词 → 声音 → 连续性 → 限制。
3. 多镜时逐镜复述人物/场景/光线锚点；台词写进提示词并标时间点。
4. 提示词写中文；名词、动作、光线具体；不要写「电影感」这类空词。
5. 完整范例和口播模板见 `references/prompt-playbook.md`。

## 6. 生成

- 调 `video_generate`：`duration` 设本镜秒数（≤15 直出；>15 自动续拍合并），`ratio`、`resolution`、`generateAudio` 按脚本。
- 总时长 ≤15 秒时**只调一次** `video_generate`：整条视频一次直出，禁止拆成多段分别生成再拼接。
- 多个独立镜头可以在同一回合并行调用；同一任务绝不重复提交。
- 画质默认 720p；要更精细再 1080p。竖屏 9:16，横屏 16:9。
- 生成通常 1–5 分钟。拿到任务 ID 就写进 `shots.json`。
- 失败按下面处理，不要盲目重试：

| 现象 | 处理 |
| --- | --- |
| 时长超限 / 封装超 15 秒 | 改成 14 秒；只有总时长 >15 秒才分段（≤15 秒的视频不允许拆段） |
| 内容审核拒绝 | 去掉真人/名人/血腥/政治/未成年风险描述，改虚构人物和中性表述 |
| 额度不足 / 鉴权失败 | 让用户检查 MetaOnticVideo 配置（`video_config`） |
| 超时 / 没拿到链接 | 用 `video_status` 查任务，不要重新提交 |
| 画面糊 / 手部畸形 / 换脸 | 只重生成该镜头，收紧人物锚点和动作描述 |

## 7. 验收

- `ffprobe` 查时长、分辨率、帧率、音轨；抽 3 帧看人脸、手、文字、穿帮。
- 对照 `script.md` 检查台词、动作、镜头、人物一致性。
- 不合格只重生成问题镜头，不整片重来；改了脚本就要重新确认。
- 验收记录写进 `production.md`。

## 8. 合成

- 单镜直接作为成片；多镜用 ffmpeg concat，参数不一致时统一重编码。
- 加字幕/BGM 只在用户提供素材或明确要求时做；不要编造版权素材。
- 输出 `final/<slug>-<n>s.mp4`。

常用命令：

```bash
# 多镜无损拼接
printf "file '%s'\n" clips/*.mp4 > clips/concat.txt
ffmpeg -y -f concat -safe 0 -i clips/concat.txt -c copy final/out.mp4

# 参数不一致时统一重编码（9:16 / 30fps / 含音频）
ffmpeg -y -f concat -safe 0 -i clips/concat.txt \
  -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2,fps=30" \
  -c:v libx264 -crf 20 -c:a aac -b:a 128k final/out.mp4
```

更多命令（抽帧、字幕、BGM、竖屏裁切）见 `references/ffmpeg.md`。

## 9. 交付

- 用 `present` 展示成片。
- 交付说明：一句话创意、规格（时长/画幅/分辨率/音轨）、文件路径、任务 ID、耗时、可改进点。
- 保留 `script.md`、`prompts/`、`shots.json` 和分段，方便用户改一镜重生成。

## 10. 边界

- 不生成真人明星、政治人物、未成年人敏感内容；不伪造新闻。
- 不承诺 100% 人脸、声线、口型一致；需要同一上游账号下的受信产物。
- 参考视频必须是上游能拉取的公网 URL；本地文件不能直接续拍。
- 合并只统一容器与编码，不修补接缝；接缝需要用户预览确认。
