# 源码架构

| 目录 | 职责 | 边界 |
| --- | --- | --- |
| app/ | 宿主与浏览器运行装配、Agent注册与工具装配、全局配置组合 | 组合模块，不实现视频剧情或供应商协议 |
| agents/ | 助手定义、专业角色提示词、预设源码 | 角色能力声明与文本，业务执行在businesses |
| businesses/video-generation/ | 视频任务、供应商接入、制作工作流、业务界面 | 负责实际生成、费用确认和任务恢复 |
| businesses/film-production/ | 创意到终审的专业创作、契约、版本与审批 | 不将文本产物冒充生成视频 |
| platform/ | Harness配置适配、安装迁移、遥测等外部能力 | 不依赖具体业务、角色、装配层或界面 |
| ui/ | 公共主题、更新、迁移与鉴权提示等界面 | 业务专用界面仍放对应业务client目录 |
| shared/ | 固定配置、版本、路径与通用工具 | 不反向依赖业务、宿主适配或界面 |
| locale/ | 插件展示元信息源码 | 构建生成安装目录的locale JSON |
| types/ | 宿主与编译环境的类型声明 | 不包含运行逻辑 |

`index.ts`与`client.ts`是稳定构建入口，分别组合app与业务模块。根目录的同名JS是构建产物，不直接编辑。公共层不能通过导入业务代码获取默认值；应将真正共享的值提取到shared，业务策略留在businesses。

业务内部按职责组织：tools处理工具边界，providers处理外部协议，workflow/workflows处理流程，runtime处理项目状态，contracts处理数据约束，client处理业务界面。不要为每个文件机械增加一层目录，也不要因共用一次就把业务策略放进shared。

此次整理不更改插件ID、配置命名空间、数据目录、包导出、工具ID或审批流程。Windows与macOS共用构建产物；相对模块引用在构建时解析，不增加运行时源码路径依赖。
